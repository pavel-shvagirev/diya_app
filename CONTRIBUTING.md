# Участие

[English](CONTRIBUTING.en.md) · [Русский](CONTRIBUTING.md)

## Подготовка

```sh
npm ci
npm start            # собрать и запустить
npm run check        # линтер + типы + проверка формата + тесты с покрытием
npm run e2e          # настоящее приложение против Диска в памяти (нужен дисплей)
```

Node.js 22+. `npm test` пересобирает `better-sqlite3` под Node, `npm start` — под Electron; если
после переключения появляется ошибка нативного модуля, выполните `npm run native:rebuild:node`
или `npm run native:rebuild:electron`.

## Правила

- Небольшие pull request'ы; одно логическое изменение на коммит (`feat:`, `fix:`, `docs:`, …).
- Изменение поведения идёт вместе с тестом; исправление ошибки начинается с падающего теста,
  который её воспроизводит.
- Не придумывайте форму ответа API в моках: берите её из официальной документации Яндекс Диска
  (<https://yandex.com/dev/disk-api/doc/ru/>) и указывайте страницу в тесте.
- Интерфейс: следуйте [docs/DESIGN.md](docs/DESIGN.md) (только токены, без жёстко заданных цветов,
  подсказка на каждой кнопке действия). Каждая видимая пользователю строка добавляется на обоих
  языках (`strings.ts`).
- Всё, что влияет на безопасность, описывайте в PR; функция с известной проблемой отключается через
  `src/shared/features.ts` и отклоняется в главном процессе.
- Для изменений, видимых пользователю, обновляйте `CHANGELOG.md` и `CHANGELOG.en.md`; пары
  документов держите согласованными (`X.md` — русский, `X.en.md` — английский: README, CHANGELOG,
  CONTRIBUTING, SECURITY, ARCHITECTURE, RELEASING, SIGN_IN).
- Не коммитьте токены, секреты клиента, личные пути и данные аккаунтов; в фикстурах только
  вымышленные значения.
- Работа с ИИ-помощником: [AGENTS.md](AGENTS.md) — памятка, которой он следует.
- Форки: зарегистрируйте своё OAuth-приложение Яндекса ([docs/SIGN_IN.md](docs/SIGN_IN.md)),
  сохраните оговорку «не связано с Яндексом», дайте сборке своё имя и значок; название и логотип
  Яндекс Диска переиспользовать нельзя (`assets/brand/NOTICE.md`).
